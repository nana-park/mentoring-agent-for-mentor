# 알려진 제한과 후속 작업

이번 변경은 폴더, import, 설정 경로, 실행 진입점 및 문서 정리입니다.
아래 항목은 코드 조사에서 확인된 기존 문제이며, 구조 정리로 해결되었다고 간주하지 않습니다.

- `pipeline.process_source()`는 이전 이력 조회에 학생 페이지 ID 대신 이름을 전달합니다.
- 일부 Notion 저장 함수가 예외를 출력만 하여 상위 파이프라인에 성공으로 전달될 수 있습니다.
  낮은 확신도로 검토 큐에 보낸 경우도 호출자는 Success로 기록할 수 있습니다.
- batch 모드는 처리 함수가 반환하면 성공 여부와 관계없이 파일 보관을 시도합니다.
- Gmail은 제목 키워드로 최대 500개를 조회하며 unread 조건, 읽음 처리, 추가 페이지 조회가 없습니다.
  성공 기록이 없는 매칭 실패 항목은 다시 검토 큐에 쌓일 수 있습니다.
- 복수 문서 메일의 source ID는 정렬되지 않은 집합의 순번을 사용합니다.
- 직접 입력 중복 ID는 제목, 학생명, 본문 첫 50자를 사용합니다.
- Raw Note 및 전역 검토 큐 원문은 최대 2,000자까지만 저장됩니다.
- 웹 처리 이력은 `db_config.json`의 한 DB를 조회합니다. 강의별 전체 이력을 통합하지 않습니다.
- AI 학생 매칭과 학생 상태 평가는 사람이 확인해야 합니다.
- `legacy/` 코드에는 과거 인터페이스, 오래된 DB 스키마, 문자 인코딩 문제가 남아 있습니다.
  현재 파이프라인은 이 코드를 호출하지 않습니다.

기존 테스트처럼 보이던 파일도 실제 외부 API를 호출하거나 데이터를 수정하는 경우가 있었습니다.
현재 `tests/`는 새 오프라인 회귀 검증만 포함하며 실서비스 동작 검증을 대체하지 않습니다.
